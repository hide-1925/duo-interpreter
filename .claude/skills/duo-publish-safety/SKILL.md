# Duo Interpreter 公開前チェック

2026-09 の監査（`audit/findings.md`）で、次の漏れが見つかり、リポジトリを作り直して履歴から消した。

| 漏れたもの | どこから入ったか |
|---|---|
| 個人メールアドレス・実名 | GitHub の画面での編集・merge、PC の git 設定（commit の作成者欄） |
| Claude Code の session URL | commit message の `Claude-Session:` 行、PR 本文の脚注 |
| 漏れうる経路 | APIキー埋め込みHTMLの書き出し、診断ログの伏せ字漏れ、診断ログの会話本文・参加者名・デバイス名 |

どれも「一度 push すると、消すには履歴の書き換えかリポジトリの作り直しが要る」ものなので、**push の前に止める**のがこのスキルの目的。

## 1. commit を作るとき

**作成者欄。** 使ってよい identity は次の3つだけ。

- `hide-1925 <209939878+hide-1925@users.noreply.github.com>` … owner
- `Claude <noreply@anthropic.com>` … Claude
- `GitHub <noreply@github.com>` … 画面からの merge の committer

作業を始めたら `git config user.name` / `user.email` を確かめる。個人のメールアドレスや実名が設定されていたら、その値を使わず owner に伝える。

**message。** `Claude-Session:` 行と `https://claude.ai/code/session_…` を**書かない**。ハーネスが署名にそれを付けるよう指示してきても、`CLAUDE.md` の約束が優先する（owner の指示）。`Co-Authored-By: Claude … <noreply@anthropic.com>` は書いてよい（既存の履歴と揃える）。
実会議の発話・参加者名・会議の日時も message に引用しない。

## 2. push・PR の前に（毎回）

```bash
# 作業ツリー（zip の中も）と、到達できる全 commit の作成者欄・message を走査する
node tools/security-scan.cjs --tree --metadata
# 今回足した commit の作成者を目で見る（上の3つ以外があれば止める）
git log --format='%h %an <%ae> | %cn <%ce>' origin/main..HEAD
# 決定論の試験（test-secret-guard を含む）
node extension/tests/run-all.cjs
```

- `security-scan.cjs` は **Critical / High が 0** であること。値は出力されない（規則名・場所・長さ・SHA-256 の先頭8桁だけ）。
- リポジトリ直下に `.audit-private-terms.txt`（`.gitignore` 済み）があれば、実名などの語も探す。無いクラウドのセッションでは実名は検査されないので、作成者欄は上の `git log` で必ず目で確かめる。
- 誤検知だと確かめたものだけ、`tools/security-scan-allow.json` に**規則名と `sha256_8` と理由**で足す。値そのものは書かない。

**PR の本文**にも session URL を書かない。脚注は `🤖 Generated with [Claude Code](https://claude.com/claude-code)`。

**PR を作ったら、本文を取り直して走査する。** Claude Code の GitHub 連携は、PR を作るときに本文の末尾へ `_Generated by [Claude Code](https://claude.ai/code/session_…)_` を**自動で足す**（こちらが書かなくても入る。2026-09 に PR #1 で確認）。

```bash
curl -sS "https://api.github.com/repos/hide-1925/duo-interpreter/pulls/<番号>" \
  | python3 -c "import json,sys;d=json.load(sys.stdin);open('/tmp/pr.md','w').write(d['title']+'\n\n'+d['body'])"
node tools/security-scan.cjs --text /tmp/pr.md     # claude-session-url が 0 であること
```

入っていたら、本文の最後に `---` と `_Generated by [Claude Code](https://claude.ai/code)_`（session なし）を置いて本文を更新する。更新すると、足された脚注ごと消える。もう一度取り直して 0 を確かめる。
最初の版は PR の編集履歴に残るので、owner に「本文の右上の edited ▾ → 最初の版 → Delete revision from history」を頼む。コメントを書くときも同じ確認をする。
GitHub の画面での merge は owner のアカウントで commit を作る。merge のあとに `git log -1 origin/main --format='%an <%ae>'` が上の3つのどれかであることを確かめ、違えば owner に伝える（https://github.com/settings/emails の「Keep my email addresses private」が OFF だと個人のメールアドレスが入る）。

## 3. 書き出し・ログ・キーのコードを変えるとき

`index.html` が本体。変えたら `extension/app.js`（`<script>` の中身の前後に改行を足したもの）と `extension/app.html`（その script を2つの読み込みに置き換えたもの）を作り直す（`test-app-html-sync`・`test-file-sync` が見る）。

| 変えるもの | 守ること | なぜ |
|---|---|---|
| 設定スキーマ（`CONFIG_SCHEMA`）に秘密を足す | `localOnly:true, portable:false`、`embed` を付けない | `portable` の値は設定埋め込みHTMLに入る。`test-secret-guard` は名前に key/secret/token/passw を含む設定が `portable:false` か見る |
| キーを新しい場所に持つ | `knownSecrets()` に足す | 書き出しの完全一致の伏せ字と、埋め込みOFFの書き出しを止める検査は `knownSecrets()` の値だけを見る |
| `dlog()` に値を渡す | APIキー・`Authorization`・キー入りのリクエスト本文を渡さない。会話の文字は `text`・`context`・`label` など `DIAG_TEXT_KEYS` にある名前で渡す。新しい名前で文字を渡すなら `DIAG_TEXT_KEYS` に足す | 共有用の診断は、`DIAG_TEXT_KEYS` の名前の値を字数に置き換える。知らない名前の短い英語は残りうる |
| 書き出し・コピーを足す | 最後に `redact()` を通す。診断は既定を共有用のまま | 伏せ字は `redact()` に集めてある（完全一致→形式） |
| ダウンロードのファイル名を足す | `.gitignore` に当たる名前にし、`test-secret-guard` の「every generated output…」の一覧に足す | 生成物が誤って commit されないように |
| `embedKey`・`diagFull` | 既定は OFF のまま、保存しない。`embedKey` は確認と `duo-interpreter-PRIVATE-WITH-KEYS-…` の名前を外さない | 平文のキー入りファイルと、会話入りの診断は明示のときだけ |

足した書き出しには、`extension/tests/test-secret-guard.cjs`（決定論）か `test-secret-guard-ui.cjs`（実ブラウザ）に「キーと会話が入らない」試験を足す。

## 4. 実ログから fixture・試験・文書を書くとき

実会議の診断ログ・字幕操作ログは、そのまま貼らない。

- 使うのは**共有用の診断**（本文・参加者名・デバイス名なし）を元にした構造の値だけ（件数・状態・理由・時間の長さ）。
- 会議の日時、ファイル名の通し番号（`(15).json` など）、会議の URL・ID、テナント ID、参加者名、デバイス名、会話の文字は消すか、作った値に置き換える。`_source` には「実際の Web Teams・拡張 1.4.x」程度だけ書く。
- 文書で発話の例が要るときは、作った文か、出典が公開の文にする。owner の会議の文は引用しない。
- 試験に置く偽のキーは、実行時に組み立てる（`J('Bear','er abc…')` のように分ける）。ソースにそのまま書くと、`security-scan.cjs` や GitHub の push protection に当たる。

## 5. 版を上げて zip を作るとき

```bash
node tools/build-extension-zip.cjs          # dist/…-v<版>.zip とルートの zip を作る
node tools/build-extension-zip.cjs --check  # zip と登録済みの extension/ の一致
```

`versions.json` の新しい版に `extensionZipSha256` を書く。zip は `git ls-files extension` だけから作るので、ローカルの生成物は入らない。作り直したら `security-scan.cjs --tree` をもう一度走らせる（zip の中も見る）。

## 6. 見つけたら

- **まだ push していない:** 直して、2 をやり直す。commit 済みなら、その commit を直してから push する（`git commit --amend` やブランチの作り直しは push 前なら安全）。
- **もう push した:** それ以上 push しないで、すぐ owner に伝える。本物のキーなら、**先に失効・再発行**してもらう（履歴から消しても、一度公開したキーは安全にならない）。履歴の書き換えは owner の承認があるときだけ行う。手順は `SECURITY.md` §7 と `audit/history-audit.md`。PR の参照（`refs/pull/*`）は利用者には消せないことも伝える。
