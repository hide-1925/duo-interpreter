## F-01 / F-02 個人メールアドレスと実名

- **Category:** PII（commit identity）
- **Location:** author 246件（実名＋メール 235、GitHub ハンドル＋メール 11）、committer 11件。メールの出現は計257か所
- **Reachability:** 全ブランチ・タグ・PR ref から到達可能。ファイルの中身には無い（全 blob と zip の中を走査して0件）
- **Evidence:** `tools/security-scan.cjs --metadata`。email 規則 fp `604736db` len 27、private-term #1（fp `1e2886af`）・#2（fp `6e2c82bd`）が commit メタデータだけで各492件
- **Remediation:** `git filter-repo --mailmap` で owner が指定する公開 identity へ置き換える。**対象の identity（このメールアドレス）に一致するものだけ**。`Claude <noreply@anthropic.com>` と `GitHub <noreply@github.com>` は変えない
- **Verification（dry-run）:** 書き換え後の全 ref で email 0件・private term 0件。306 commit 全ての tree が元と同一、author/committer の日時も同一
- **Status:** 解消。公開 identity は owner の指定で `hide-1925 <209939878+hide-1925@users.noreply.github.com>`

## F-03 Claude Code session URL（commit message）

- **Category:** 不要な識別子
- **Location:** commit message の末尾の `Claude-Session: https://claude.ai/code/session_…` 行。70 commit、URL は2種類
- **Remediation:** `--message-callback` でこの行を削除し、本文中に URL だけが残る場合も削除する。`Co-Authored-By: Claude …` の行は残す（下記の方針）
- **Verification（dry-run）:** 書き換え後の全 ref で session URL 0件、`Claude-Session` 行 0件。message の中の短縮 SHA（9 commit・12か所）は filter-repo が新しい SHA に書き換え、12か所すべてが新しい履歴の commit を指す
- **方針:** `Co-Authored-By: Claude … <noreply@anthropic.com>` は機密ではないので、既存の履歴と揃えて残す。今回の commit も同じ形（session URL なし）にした

## F-05 PR ref に旧 commit が残る

- GitHub の `refs/pull/N/head` は利用者が push でも削除でも消せない。書き換えを force push しても、26本の PR ref は**旧 commit（メール・実名・session URL 入り）**を指したまま残り、PR の画面の「Commits」からも見える
- 監査時点でリポジトリは **private・fork 0**。いま外部から見えるのは Pages だけ
- 選択肢（`public-release-checklist.md`）:
  - **A.** 同じリポジトリへ force push し、GitHub Support に PR ref とキャッシュの削除を依頼する。完了まで private のまま
  - **B.** 書き換えた履歴を新しいリポジトリへ push し、古いリポジトリは削除する（同じ名前で作り直せば URL・Pages の URL も保てる）。PR の記録（本文）と Release は失われるので、Release は作り直す
- **推奨: B。** private・fork 0 なので、作り直しなら旧 object への到達経路が確実に無くなり、Support の対応を待つ必要も無い。削除は取り消せないので owner の判断
- **結果:** owner が B を選び、2026-09-28 に作り直した。旧 SHA は `GET /commits/{sha}` で 422、`refs/pull/*` は0本

## 残るリスク

- 実キーは見つからなかったが、**GitHub の外（利用者の端末・共有した診断ログ・渡したHTML）**にあったものは検査の範囲外
- 書き換えても、GitHub のキャッシュ、clone 済みの端末、検索エンジンのキャッシュから旧 commit が消えるとは言えない（private・fork 0 なので範囲は owner と共同編集者の端末に限られる）
- Wiki の中身・Pages の配信物は未確認（F-21）
- 共有用の診断は、本文を運ぶキーの名前（と英数字記号だけの短い値かどうか）で落としている。将来 `dlog()` に新しい名前で本文を渡すと、80字を超えるか英数字以外を含む値は字数になるが、短い英語だけの値は残りうる
