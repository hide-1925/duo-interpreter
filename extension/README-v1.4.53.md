# Duo Interpreter 拡張 v1.4.53

HTML 本体 **v1.52.0**（ビルド `20260930-v1520-stt-auto-fallback`）と対です。

`STTマルチプロバイダ開発仕様書.md` §14.3 の**自動フォールバック**です。owner の指示（D-3 追記）どおり、
**ON／OFF の選択式にし、ON のときは切り替え先の優先順位を先に決めておく**形にしました。
**既定は OFF で、OFF のままなら v1.51.0 と同じ動きです。**

## 1. 足したもの

| | 内容 |
|---|---|
| 設定 | ⚙→音声→ストリーミング認識の設定に「自動フォールバック」（OFF（既定）／ON）。ON のときだけ「予備1〜3」（なし／OpenAI gpt-live／ElevenLabs／AssemblyAI／Soniox）と「切り替えの順：…」が出る。キーの無い予備には印が付く |
| 順 | 選んでいる会社 → 予備1 → 予備2 → 予備3。「なし」・選んでいる会社と同じもの・重複は除く。順は「開始」のときに決まる |
| 切り替える場面 | 開始時に一時的な理由（429・5xx・通信断・CORS で届かない・タイムアウト）でつながらないとき。途中で切れて、つなぎ直しを1分に3回使い切ったとき。gpt-live の WebRTC が failed になったとき |
| 切り替えない場面 | 選んでいる会社のキーの誤り・キーが無い・設定の誤り（誤りを隠さないため）。音声の入力そのものが止まったとき |
| 予備での失敗 | 理由によらず次の予備へ。すべてだめなら「○○→△△ を試しましたが、つながりませんでした（最後：…）」で止まる |
| キーとモデル | 予備はその会社のキーと既定のモデルだけを使う。予備の OpenAI は OpenAI の音声認識のキーか翻訳の OpenAI のキーだけで、選んでいる会社の欄のキーを OpenAI へ送らない |
| 知らせ方 | 開始時は「○○ につながらないため、自動フォールバックで △△ に切り替えました。」。途中は「音声の送り先を ○○ から △△ へ切り替えます」。診断に「自動フォールバック」の行（順と切り替えの記録）、動作ログに `live-fallback` |

切り替えは「停止」まで続き、設定は書き換えません。次の「開始」は選んでいる会社から始まります。

## 2. 変えていないこと

- 自動フォールバックが OFF のときの動き（`test-stt-live-parity` は v1.49.39 と突き合わせたまま通る）。
- 各社の接続・送る設定・受信の扱い、再接続の回数と待ち時間、カードの閉じ方。

## 3. 検査

- `test-stt-live-host`（決定論・30件、うち自動フォールバック11件）… OFF では切り替えない、ON では順どおり、
  429・CORS でも次へ、選んでいる会社の auth・config では切り替えない、キーの無い予備を飛ばす、予備の OpenAI に別の会社のキーを送らない、
  予備の失敗で次へ・最後の文言、「なし」と重複を除く、再接続を使い切ったら切り替える、ベンチ（`fallback:false`）では切り替えない、
  gpt-live の failed、診断の行。
- `test-stt-stream-ui`（実ブラウザ・9件）… Soniox の発行先が 503 を返すとき、OFF なら止まり、ON なら同じ音声が AssemblyAI へ流れ、
  受信からカードができ、停止で Terminate を送る。
- `test-stt-settings-ui`（実ブラウザ・13件）… OFF で予備の欄が隠れ、ON で出て、選択肢・順の表示・保存が合う。
- `test-stt-live-adapters`（14件）… モデル名の欄は選んでいる会社のもので、予備は既定のモデルになる。
