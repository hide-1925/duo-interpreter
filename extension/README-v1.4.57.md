# Duo Interpreter 拡張 v1.4.57

HTML 本体 **v1.54.1**（ビルド `20261013-v1541-live-cadence`）と対です。

ElevenLabs の音声認識で、語や文の途中で翻訳・読み上げに回っていた不具合の修正です。拡張の側のコードは変えていません。

## 1. 直したこと：途中経過の仮の「。」で確定していた

ElevenLabs のストリーミング認識は、途中経過をおよそ1秒ごとに「区間の全文」で送り直し、末尾に仮の「。」を付けてきます。次の途中経過でその「。」が消えたり、語の続きに書き換わったりします。

Duo は「文字が 0.3〜0.4 秒変わらなければ安定」と見て、安定した部分の「。」までを確定していました。そのため、次の途中経過が届く前に仮の「。」までが確定し、語や文の途中で翻訳・読み上げに回っていました。v1.54.0 の実測（ElevenLabs・fast）では、確定 54 件のうち 18 件が確定後に書き換わり、3文字で切れた部分がそのまま読み上げられました。

| | 内容 |
|---|---|
| 待ち | gpt-live 以外のストリーミング認識（ElevenLabs・AssemblyAI・Soniox）では、安定待ちを「途中経過が届く間隔の直近5回の最大＋0.1秒」より短くしない。最初の2回を測るまでは1秒とみなす。上限は1.6秒 |
| 間隔の数え方 | 文字が変わらなかった途中経過も数える。発話の切れ目の長い間（2.5秒超）は数えない |
| 対象外 | gpt-live（追記だけで、確定した文字が後から変わらない）、ブラウザ内蔵、録音分割 |
| 設定 | 「認識の安定待ち」に大きい値を入れていれば、そちらが優先。小さい値は上の床まで引き上げる |
| 記録 | `stt live-cadence`（間隔と待ち。本文なし）。床が効いた `segment commit` に `windowMs` |
| 代わりに | 文の途中の確定は約0.8秒遅くなる。文の終わりの確定は ElevenLabs の無音の合図で来るので変わらない |

## 2. 検査

- `test-stt-live-host` に5件：仮の「。」を次の途中経過の前に確定しない、gpt-live は今までどおり、生き残った「。」は次の途中経過の直後に確定し待ちを記録する、間隔の数え方（直近5回の最大・変わらない途中経過・長い間）、床の上限と利用者の設定。
- 床を外す、変わらない途中経過を数えない、最大でなく平均にする、gpt-live にも当てる、の4つをそれぞれ入れると落ちることを確かめた。
