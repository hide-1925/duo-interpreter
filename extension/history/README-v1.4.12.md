# Duo Interpreter Chrome/Edge 拡張 v1.4.12

**HTML v1.49.1 と対で動きます。**

## 1. 判断層が「到達できない」まま黙っていた問題

実機で shadow にして Jev のキーを入れたところ、`Failed to fetch` が3回続いて
回線遮断が開き、以後は旧ルールで動き続けていました。**動作としては設計どおり**ですが、
理由が分からないまま「shadow にしたのに何も起きない」に見えます。3点直しました。

### 記載の無いヘッダを既定で送るのをやめた

`X-TypeSafe-Zero-Data-Retention` と `X-TypeSafe-No-Training` を常に送っていました。
**公式リファレンスに記載が無く、こちらで足したものです。** 別オリジンへ投げると
preflight（OPTIONS）が走り、サーバが `Access-Control-Allow-Headers` にこの名前を
並べていなければ本リクエストは発射されず `Failed to fetch` になります。
実在を確認できていないヘッダのために疎通を落とすのは本末転倒なので、既定では送りません。
必要と分かれば経路の `extraHeaders` を `true` にするだけです。

### 到達不能を切り分けられるようにした

ブラウザは CORS でも DNS でも遮断でも同じ `TypeError: Failed to fetch` を投げ、
`status` が付きません。これを `unreachable` として印を付け、HTTP エラーや中断
（タイムアウト）と混ぜないようにしました。到達できないときは一度だけ通知も出します。

### 疎通確認のボタンを足した

⚙→音声→判断層に **「この経路へ疎通を試す」** を追加しました。判断層のモードに
依存しないので **off のままでも試せます**。実際の契約と同じ形の本文を1回だけ投げ、
結果を切り分けて出します。

| 結果 | 意味 |
| --- | --- |
| 到達しました（N ms） | この経路は使えます |
| 到達できません（CORS） | ブラウザから直接呼べない可能性。プロキシが要ります |
| HTTP 401 / 403 | サーバまでは届いた。キーの問題 |
| HTTP 404 | Base URL と経路の問題 |

会議を1本回さないと分からなかったものが、1クリックになります。

## 2. あわせて直したログの誤り

`turn-decision-request` が `model:""` と出ていました。実際には経路の既定
（`jev-latest`）が使われています。送った値を出すようにしました。

## 3. 入れ替え方

1. 最新版 ZIP を**空のフォルダー**へ展開する（古いフォルダーへの上書きは避ける）
2. `chrome://extensions` で既存の Duo Interpreter を**削除**する
3. 「パッケージ化されていない拡張機能を読み込む」で 1 のフォルダーを指定する
4. popup の見出しが **`Chrome v1.4.12`** と出ることを確認する
