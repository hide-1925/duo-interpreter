# Duo Interpreter 拡張 v1.4.28

HTML 本体 **v1.49.17**（ビルド `20260924-v14917-stability-range`）と対です。

## 認識の安定待ちを、10ms刻み・100〜2000ms にしました

⚙ → 音声 → TTS逐次読み上げ → 逐次読み上げの詳細設定 → **認識の安定待ち ms**

|項目|変更前|変更後|
|---|---|---|
|刻み|50ms|**10ms**|
|実際に効く下限|**200ms**|**100ms**|
|上限|2000ms|2000ms（変更なし）|
|`0` の意味|モード既定|モード既定（変更なし。fast 300ms / balanced 400ms）|

**下限は入力欄ではなくコード側で丸められていました。** 欄は `min="0"` のまま（`0`＝既定の
合図）なので、100 と入力しても `segNumber(...,200,2000)` が 200 へ持ち上げていました。
**画面には100と出たまま200で動く**という、いちばん分かりにくい形です。これを直しました。

ラベルにも使える範囲を書きました（`認識の安定待ち ms（0＝既定 / 100〜2000）`）。

### これが効く場所

認識した文字が「もう変わらない」と見なすまでの待ち時間です。短くすると区切りの判断が
早く始まり、長くすると認識の揺れに強くなります。**下げると訂正が増える可能性があります**
（診断の「逐次確定・訂正」でご確認ください）。

## テスト

**決定的 435 件 + E2E 13 件 = 448 件 全通過。**

新設 `test-segment-policy`（6件）。**入力欄とコードの丸めが食い違わないこと**を検査します。

- 安定待ちの欄が 10ms 刻み・上限2000・`min="0"`（既定の合図）であること
- **100〜2000 の全ての値が、丸められずそのまま使われる**こと
- **使える範囲がラベルに書いてある**こと（書いていない範囲を黙って丸めない）
- `0` は下限への丸めではなく**モード既定**になること
- モード既定（300 / 400）が範囲の内側にあること
- **最小文字数・無音区間・待ち音声の欄も同じ一致を保っている**こと

最後の1件で、隣の欄に同じ食い違いが無いことも確認しています（現状すべて一致）。
