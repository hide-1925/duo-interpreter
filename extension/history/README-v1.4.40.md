## アドオンの字幕表示で Web Speech が認識しなかった件

v1.49.26 の記録では、アドオンの字幕表示（タブ音声）で Web Speech を選ぶと認識が一度も始まりませんでした。

- 開始から約0.15秒で `network` のエラーが返り、再起動しても同じでした（22回）。
- 同じ Chrome（153）で、HTML の画面共有の音声なら Web Speech で認識できていました。
- 同じタブ音声でも、gpt-4o-mini-transcribe や gpt-live なら字幕も翻訳も動きました。

Chrome がアドオンのタブ音声（tabCapture）を Web Speech の認識サーバへ渡せていないと見ています。
Chrome の中の問題なので、こちらから直せるとは限りません。そこで次のようにしました。

1. 一度も結果が来ないまま、開始から1.5秒以内の `network` が2回続いたら、同じ音声を WebAudio で
   1ch（16kHz）に通した音声に替えて、もう一度試します。
2. それでも同じなら、再起動を続けずに止め、次の案内を出します。
   - ⚙→音声認識で gpt-4o-mini-transcribe などの外部 API を選ぶ
   - アドオンの字幕表示を使わず、HTML 本体の画面共有で Web Speech を使う
3. 一度でも認識できた後の `network` は、従来どおり待って再起動を続けます（回線の一時的な切れと区別できないため）。

**中継した音声で直るかどうかは、まだ分かりません。** headless Chromium では、中継した音声でも
Web Speech が開始して音声を受け取るところまでは確認しました。ただしこの環境からは Google の
認識サーバに届かないため、結果が返るかは実機で確かめる必要があります。
診断ログの `track-relay`（中継に替えた）と `track-heard`（認識が始まった）を見てください。

## 読み上げ（Aivis）の待ちを3つ短くしました

### 1. 次の部分を先に頼んでおく（先読み）

読み上げは1件ずつで、次の部分の合成は、前の音が鳴り終わってから頼んでいました。Aivis は最初の音まで
0.2〜0.5秒かかるので、部分が替わるたびにその分の無音が挟まっていました。

前の音の受信が終わり、鳴り終わりまで約1.2秒になったら、次に読む部分の合成を先に頼みます。

- **鳴らすのは前の音が終わってから**です。声は重なりません。
- 先に頼んだ本文と、実際に読む本文・声・話速が1つでも違えば、先に頼んだ音声は捨てて頼み直します。
- ストリーミング再生のときだけ効きます。
- 設定：⚙→音声→Aivis→**次の部分の先読み**（既定は「先読みする」）。

**頼む回数は増えます。** 読み上げが話し手に追いつくので、まとめて頼める部分が減るためです。
代役の Aivis で6文を読むと、4回が6回になりました。
直近60秒に8回以上頼んでいるときは先読みせず、従来どおりまとめて頼みます。

### 2. 文末を待つのは1.2秒まで

Aivis には文の途中で渡さないよう、「。」が来るまで待っていました。この待ちは、カードが1.5秒以内に伸びているあいだ続きます。
そのため句点の来ない話し方では、話し終わるか500字に届くまで読み上げが止まっていました
（これまでの記録で平均3.4秒、最長15秒）。

この待ちを、その部分が読める状態になってから**1.2秒まで**にしました。前の音を鳴らしているあいだも
時計は進むので、鳴り終わった時点で1.2秒を過ぎていれば、もう待ちません。

### 3. 「。」で切るときは判断層の答えを待たない

判断層が active のとき、確定の直前に、答えを最大0.3秒待っていました（INV-10）。

Rules が「。」「？」「！」で切るときは、この待ちをやめました。
句点の位置は判断層に聞いても変わらないためです（v1.49.26 の日本語の記録で、往復383件のうち判断層が切った部分は0件）。
句点の無い位置で切るときは、従来どおり待ちます。答えがすでに届いていれば、従来どおりその答えに従います。

## 実ブラウザでの確認

headless Chromium で確認しました。Aivis は代役です（最初の音まで約0.3秒、実際の約10倍の速さで合成）。
gpt-live のイベントで日本語の文を6つ流して原文を読み上げました。鳴らし始めの余白（lead）は、お使いの記録と同じ150msにしました。

**部分の切り替わりの無音**（前の音の終わりから、次の音の始まりまで）

| | 平均 |
|---|---|
| v1.49.28 | 約640ms |
| 先読みする | **約360ms** |

**文ごとの遅れ**（その文が確定してから、その文の最初の音が鳴るまで）

| 話す速さ | 先読みなし | 先読みする |
|---|---|---|
| 2.0秒に1文 | 約470ms | 約470ms（先読みが要らない） |
| 1.5秒に1文 | 約1.2秒 | **約0.5秒** |
| 1.15秒に1文 | 約1.7秒 | **約1.4秒** |
| 0.8秒に1文 | 約2.1秒 | 約2.0秒（どちらも追いつけない） |

**効くのは、話す速さが読み上げの速さに近いとき**です。先読みしないと1文ごとに約0.3秒ずつ遅れが
積もり、先読みすると追いつけるようになります。

**文末待ち**：句点の来ない約110字の発話を、長さで確定させました。最初の部分を送るまでが 6.3秒から 1.2秒 になりました。

**判断層の待ち**：文ごとの確定文が一度に届く場合（録音分割の代わり）で比べました。
判断層の代役は、答えるまで250msかかるものです。
v1.49.28 では6文のうち2文が約0.32秒待たされていました。v1.49.29 では0文です。

これらはすべて代役での数字です。実際の Aivis の最初の音までの時間は、記録では0.2〜0.5秒でした。

## 残っている待ち（今回は変えていません）

先読みしても、部分の切り替わりに約360msの無音が残ります。

| 残っている待ち | 長さ |
|---|---|
| 前の音が終わってから、読み上げ枠を空けるまでの余裕 | 150ms |
| 次を送り出すまでの見回り | 最大80ms × 2 |
| 鳴らし始めの余白（lead） | 150ms |

縮めるかどうかは、実機の記録を見てから決めます。
