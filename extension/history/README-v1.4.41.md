## 音は届いているのに Web Speech が文字を返さなくなる件

v1.49.29 の記録（画面共有の音声・Web Speech・相手(B)＝日本語）を見ると、次のとおりでした。

- 1回目の開始では、8秒間なにも返らずに終わりました。始め直した後も、20秒近く何も返らないまま、終わりもしませんでした。
- 2回目の開始では、「日本の」→「日本」を返した後、38秒間ひとつも結果が来ませんでした。このときも終わりませんでした。
- そのあいだ、共有音声の入力レベルは話し声の大きさを示していました（読み上げ中の重なりの推定は90%）。音は Chrome まで届いています。

**アプリが結果を捨てた跡はありませんでした。** 捨てたときに出る記録（`noise-drop`・`echo-drop`・カード削除）は1件もありません。
会話カードに出た4文字が2文字に減ったのは、Chrome が自分の途中結果を書き直したためです。

Chrome の認識は、結果を返さないまま終わりもしないと、こちらの再起動の仕組みが働きません。そこで次の2つを入れました。

### 始め直す

最後の結果（または開始）から10秒、その半分以上の時間で音が鳴っていたら、認識を止めて同じ音声で始め直します。

- 止めても終わらないときは、認識のオブジェクトごと作り直します。
- 無音のあいだは何もしません（Chrome が自分で終わって始め直します）。
- 音楽だけが流れているときも同じ条件になります。そのため、続けて始め直すたびに待ちを倍にします（10→20→40秒、最大60秒）。結果が1件でも来れば10秒に戻します。
- 2回続けて始め直したときは、言語の設定を確かめるよう1回だけ表示します。流れている音声の言語と、相手(B)の言語が合っていないと、Chrome はほとんど文字を返しません。

### 次の記録で切り分けられるようにする

| 記録 | 中身 |
|---|---|
| `track-restart` | 認識1回ごとに、続いた時間、返った結果の数、Chrome が音・発話を検出するまでの時間、終わった理由（`no-speech`・`aborted`・`stall`） |
| `track-stall` | 始め直したときの、無結果の時間と音の割合 |
| `app ERROR`／`REJECT` | 捕まえていない例外（30件まで） |

これまでは、音声認識の中で例外が起きても、どこにも残りませんでした。

## 確認したこと

- headless Chromium で、認識の代役に「日本の」「日本」を返させた後、音を流したまま結果を止めました。
  - 最後の結果から約10.4秒で始め直しました。
  - 次の結果は新しいカードに入り、前のカード（「日本」）は確定しました。
- Node の検査で、次のことを確かめました。
  - 待ちが 10→20→40→60→60秒 と伸びること
  - 結果が来れば10秒に戻ること
  - 無音と、音が3分の1程度のときは始め直さないこと
  - 止めても終わらないときに作り直すこと
  - 停止や失敗で見張りが止まること

**実際の Chrome が始め直して文字を返すようになるかは、まだ確かめていません。** 次の記録で `track-stall` の後に結果が続いているか見てください。
