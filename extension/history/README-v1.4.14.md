# Duo Interpreter 拡張 v1.4.14

HTML 本体 **v1.49.3**（ビルド `20260923-v1493-extension-transport`）と対です。

## この版でやったこと

**判断層（Jev）への往復を、アドオンのバックグラウンドが肩代わりします。**

### なぜ必要になったか

PowerShell から `api.typesafe.ai` を直接叩いて確定しました。

```
-- 判定 -------------------------------------------------
  API は動いています。
  ただし CORS 応答ヘッダがありません。ブラウザからは結果を読めません。
```

つまり **API もキーも契約も問題なく、ブラウザが結果を読めないだけ**でした。サーバが
`Access-Control-Allow-Origin` を返さないので、ブラウザは応答を破棄して
`TypeError: Failed to fetch` を投げます。ステータスも付きません。v1.49.0 と v1.49.1 で
同じ 138〜139ms の失敗が出ていたのはこれです。**ブラウザからの直叩きは成立しません。**

拡張は、利用者が許可したホストに対してこの制約を受けません。そこで往復だけを
拡張に肩代わりさせます。**新しいサーバも中継業者も要りません。**

### 経路

⚙→音声→判断層 の経路に **「Jev — アドオン経由（CORS回避）」** が増えます。
リクエストの形は「Jev — TypeSafe に直接」と**同一**です。変えているのは運び方だけで、
検査でバイト一致を確かめています。

|使い方|運び方|
|---|---|
|拡張版（アドオンの「HTML本体を開く」で開くページ）|`chrome.runtime` でバックグラウンドへ直接|
|HTML 本体（GitHub Pages）|ポップアップで接続したときに張られる内容スクリプト経由|

どちらも鍵と本文はこのブラウザの中しか通りません。**第三者の中継は経由しません。**

## 使う手順

1. ポップアップの **「判断層（Jev）の接続先」** に `https://api.typesafe.ai` を入れ、
   **「この接続先を許可」** を押す（Chrome が許可を聞きます）
2. HTML 本体の ⚙→音声→判断層 で経路を **「Jev — アドオン経由（CORS回避）」** にする
3. **「この経路へ疎通を試す」** を押す
4. 「到達しました」と出れば使えます

判断モードは `off` のままでも 3 は押せます。

## 踏み台にしないための縛り

中継は判断層への往復だけです。何でも投げられる中継を作ると、拡張を入れている
だけであらゆるサイトの同一オリジン制約を迂回できてしまいます。4つ縛っています。

1. 中継先は**利用者がポップアップで明示的に許可したオリジン1つだけ**
2. **HTTPS のみ**
3. 通すヘッダは allowlist だけ（`Authorization` / `Content-Type` ほか経路が実際に使うもの。
   **Cookie も Origin も持ち込めません**）
4. 頼めるのは**拡張自身のページと、登録済み HTML 本体のタブだけ**（Teams 側の
   内容スクリプトからは頼めません）

送信本文 256KB・応答 1MB・30 秒で打ち切ります。**本文も鍵も拡張側では記録しません。**

鍵が DOM イベントに載る点について。同じページの他スクリプトからは読めます。ただし
鍵はもともと同じページの `localStorage` にあるので、そこを読める相手はイベントを待つ
までもありません。**露出は増えていません。**

## 中継された失敗の見分け

「到達できない」を全部 CORS のせいにすると原因を取り違えます。分けて出します。

|表示|意味|
|---|---|
|アドオンを経由できません|HTML 本体がアドオンに未接続。ポップアップの「HTML本体を開く」で接続|
|アドオンの接続先が未許可です|ポップアップの「この接続先を許可」がまだ|
|サーバまでは届きましたが拒否されました（HTTP 401）|キーの問題。中継は成功している|
|到達できません（CORS）|直叩き経路での失敗。アドオン経由をお試しください|

中継された HTTP エラーは**ステータスを保ちます**。これを落とすと 401/404 で
判断層を止める仕組み（NEVER_RETRY）が効かなくなるため、検査で縛っています。

**中継できないときに直叩きへ勝手に落ちることはありません。** 落ちれば必ず失敗し、
しかも理由が CORS に見えて原因を取り違えるためです。これも検査で縛っています。

## 検査

```
NODE_PATH=$(npm root -g) node extension/tests/run-all.cjs --with-e2e
```

新設 `test-turn-proxy`（26件）で拡張側の中継を検査します。許可外オリジンの拒否、
HTTP の拒否、権限が外れたときの停止、ヘッダ allowlist、頼める相手の限定、
ステータス保持、タイムアウト、鍵と本文が応答に混ざらないこと。

`test-turn-providers` に13件追加。直叩きとのリクエスト一致、中継不可時に直叩きへ
落ちないこと、`chrome.runtime` 経路と内容スクリプト経路の往復、別 id の応答を
取り違えないこと、中継が消えたときに待ち続けないこと、中断の伝播。

## 変わっていないもの

- `turnDecisionMode` の既定は `off`
- 判断層のキーは書き出しに載りません（`portable:false` / `localOnly:true`）
- 翻訳や TTS のキーを判断層が借りることはありません
- 判断層が届かないときは Rules で動き続けます（INV-08）
