# Duo Interpreter 拡張 v1.4.55

HTML 本体 **v1.53.1**（ビルド `20261002-v1531-overlay-stt-stop`）と対です。

実機（ElevenLabs）の診断ログで見つけた不具合の修正です。拡張の側のコードは変えていません。

## 1. 直したこと：画面取込を閉じると、共有音声の認識が黙って止まっていた

入力元を「タブ／システム音声」にし、画面取込オーバーレイの音声で認識しているとき、オーバーレイを閉じると
（またはブラウザの共有バーで共有を止めると）、認識が使っていた音声Trackも止まります。今までは次のようでした。

- 何も知らせずに共有音声の認識だけが止まり、「認識が途中で止まった」ように見えた（マイクの認識は続いていた）。
- 表示中だったカードが、全体を止めるまで「続きを待っています」のまま残った。
- もう一度取り込んでも、認識は戻らなかった（取込対象の「切替」のときだけ張り直していた）。

v1.53.1 では次のようにしました。音声認識の会社によらず同じです。

| | 内容 |
|---|---|
| 知らせる | 「画面取込を閉じたため、共有音声の認識を止めました。マイクの認識は続いています。画面取込でもう一度取り込むと、共有音声の認識を再開します。」（共有を止めた・音声が途切れたときは理由を変える） |
| カード | 開いていたカードをその時点の本文で閉じる（理由 `source-stopped`）。訳と読み上げは続く |
| 再開 | 同じ認識の回のうちに取り込み直したら、共有音声の認識だけを始め直す。マイクの認識と読み上げの待ち列には触れない。VB-CABLE とリアルタイム同時通訳は対象外（画面取込を使わない・別の経路） |
| 記録 | `overlay stt-stopped`、`overlay source-restart-stt`（理由「取込再開」） |

  マイクの認識は残る。取り込み直すと共有音声の認識だけが新しい接続で始まり、2回目は再開しない。
