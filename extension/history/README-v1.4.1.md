# Duo Interpreter 拡張 v1.4.1 — TeamsへのTTS接続修正

HTML本体 v1.47.0 と組み合わせて使用します。HTMLファイルの交換は不要です。

## 差し替え手順

1. ZIPを解凍し、中のファイル・フォルダーを、現在読み込んでいるDuo拡張のフォルダーへ上書きします。`manifest.json` が同じ階層にあることを確認してください。新しいフォルダーへ入れ子にしないでください。
2. Chromeの拡張機能管理画面でDuoの再読み込みボタンを押し、版が **1.4.1** になったことを確認します。
3. **TeamsのページとDuo本体のページを再読み込み**し、Teamsの会議へ入り直します。拡張の更新だけでは、開いたままのページに残る旧コードは切り替わりません。
4. 通常どおりDuoを開始し、Teams上の「web会議マイク音声」をONにします。

Teams側のミュートは送出より優先されます。接続解除時は元のマイクへ復帰します。
今回、APIキーの変更、仮想オーディオドライバーの導入、管理者権限でのインストールは追加していません。

## 修正内容

- `MediaStreamTrack.clone()` と `MediaStream.clone()` によるマイク複製の由来を追跡します。
- Web Audioで加工した音声について、接続元が確認済みのマイクだけで構成される場合はマイクとして検出します。
- 保存済みのRTCPeerConnectionコンストラクターを使った場合も、送信メソッドから接続を捕捉します。監視開始前に作成され、その後メソッドが一切呼ばれない接続の遡及発見はできないため、更新後のTeams再読み込みが必要です。
- 権限のあるTeamsのフレームを調べ、マイクを検出した会議フレームに接続します。別サービスの埋め込みフレームへの権限は追加しません。
- 会議接続の通信相手はタブ・ドキュメント・フレーム・接続トークンで照合します。複数のフレームに候補がある場合は自動選択しません。
- 接続に使う内部の中継用通信を、Teams本来の会議通信と区別します。
- 画面共有、相手の音声、由来を確認できない加工音声は置き換えません。加工経路に不明な音声が加わった場合は送出を解除します。

## 追加される診断ログ

既存の「字幕操作ログ」のJSONに `conference` を含めます。会議接続数、音声送信数、マイク候補数、取得・複製の回数、除外理由、フレームの識別情報と接続エラーが保存されます。
会話本文、録音音声、APIキー、マイクのデバイス名はこの追加診断には含めません。既存HTML診断ログに含まれる会話本文の扱いは変更していません。
ログは既存の診断ダウンロードに含まれ、自動で外部へ送信する機能は追加していません。

## 検証結果と限界

Node VMによる再現・回帰テスト96件、JavaScript等31ファイルの構文チェックが成功しています。内訳は `validation-v1.4.1.json` を参照してください。
複製・加工マイクの検出、画面共有・相手音声の除外、別フレームの選択と送信元照合、ミュート維持、接続解除と元マイクの復帰、診断JSON保存を検証しました。
実際の企業Teams会議での音声到達は未検証です。実ブラウザーでのループバック検証スクリプト `tests/test-browser.cjs` も同梱していますが、作業環境のブラウザー取得制限により未実行です。
由来を追えない専用の音声加工方式や、対応外のオリジンで動く会議処理はこの版でも接続できない場合があります。

## ソース

実行コードは全て同梱しています。音声の由来追跡は `conference-adapters/mic-provenance.js`、Teamsの送信差し替えは `conference-adapters/teams.js`、会議フレームの選択は `audio-bridge/controller.js` にあります。
本体のソース分割は、この修正では行っていません。
