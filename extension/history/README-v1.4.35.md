# Duo Interpreter 拡張 v1.4.35

HTML 本体 **v1.49.24**（ビルド `20260926-v14924-typed-tts-skip`）と対です。

## キーボードで入力した文が読み上げられなかった件

**翻訳の停止・実行とは関係ありませんでした。** ログの4件は、停止中の2件（e1・e4）も
実行中の2件（e2・e3）も、同じ理由で外れています。

```
読み上げ対象      | B2A（相手(B)の発言のみ）
text detect       | seat A（日本語 → 言語A=ja の席）
e1〜e4            | audio cancelled（not-selected-or-empty）
```

打ち込んだ日本語は、言語A（ja）の席＝**自分(A)の発言**として扱われます。
読み上げ対象が「**相手(B)の発言のみ**」なので、自分(A)の発言は読み上げの対象外です。
声で話したときと同じ規則で、ここまでは設定どおりの動きです。

問題は2つありました。

### ① 読み上げなかった理由が分からなかった

診断には `not-selected-or-empty` としか出ず、「対象外」なのか「本文が空」なのか
区別できませんでした。画面にも何も出ていませんでした。**`speak()` 側には3回連続で
案内する仕組みがあるのに、逐次読み上げの経路には無かった**ためです。

- 理由を分けました：`tts-target-B2A` / `tts-target-A2B`（読み上げ対象外）、`empty`、
  `tts-off`、`conference-original-only`、`self-recognition-guard`。
- **打ち込んだ文が対象外で外れたときは、1回目から案内します**（明示的に出した文なので）。
  声のときは従来どおり3回連続で案内します。どちらも1セッション1回です。

> 入力した文は自分(A)の発言として扱ったため、読み上げ対象「相手(B)の発言のみ」から外れ、
> 読み上げていません。⚙→音声 の「読み上げ対象」を「両方」にするか、
> テキスト入力の話者を切り替えてください。

### ② 打ち込んだ文にも判断層がかかっていた

同じログで、判断層（Jev・active）が**打ち込んだ文1件ごとに3往復**し、
HOLD の確率（0.34〜0.39）が上限を超えたため **2.0〜2.1秒止めてから確定**していました。

```
e1  turn-decision-request ×3 → turn-decision-hold-expired waitedMs 2087 → commit
e2  〃                                         waitedMs 2079
e3  〃                                         waitedMs 2080
e4  〃                                         waitedMs 2002
```

**打ち込んだ文は発話ではありません。** 話し終わりを判定する相手がいないので、
判断層には聞かないようにしました。12往復（入力約1万5千トークン）がまるごと無駄で、
しかも2秒の遅れを足していました。声の発話は従来どおり判断層を通ります。

## いま読み上げたいとき

どちらかにしてください。

- ⚙ → 音声 → **読み上げ対象** を「**両方**」にする
- テキスト入力の話者を **B** にして送る（相手(B)の発言として扱われ、読み上げ対象に入ります）

## 確かめたこと・確かめていないこと

- 実ブラウザで、読み上げ対象「相手(B)の発言のみ」のまま日本語を入力すると
  `tts-target-B2A` で外れ、上の案内が1回出ることを確認しました。「両方」に変えると
  読み上げへ回ることも確認しました（試験環境には合成音声が無いので、音は出ていません）。
- 判断層を飛ばすことは試験で固定しましたが、Jev 経由での実機確認はしていません。
