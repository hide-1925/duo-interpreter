## 音声認識に OpenRouter を足す

⚙→音声認識 の「サービス」に「OpenRouter（各社の文字起こしモデル）」が増えました。

- モデルの一覧は OpenRouter から取ります（キーが無くても取れます）。
  - モデルが空なら、よく使われているもの（おすすめの「人気」の1位）を入れます。
- 「🔎 選ぶ」で、文字起こしに使えるモデルだけから選べます。
  - 「試しに使う」は0.6秒の無音を送り、通るかどうかと何秒かかるかを見ます（文字は返りません）。
- キーは、音声認識欄が空なら、翻訳欄の OpenRouter のキーを使います。ほかのプロバイダのキー（翻訳が OpenAI のときの OpenAI のキーなど）は、OpenRouter へ送りません。

### 送り方

`POST /audio/transcriptions` に JSON で送ります（音声は base64 の `input_audio`）。

| 項目 | 中身 |
|---|---|
| `language` | 席の言語。AUTO で2人の言語が違い、1本のマイクを共有しているときだけ送らない（v1.49.31 と同じ決まり） |
| `input_audio.format` | 録音の形式（`webm` など） |
| 用語集 | OpenRouter の STT には `prompt` がありません。OpenAI の文字起こしモデル（`openai/…`）に限り、提供元への追加指定（`provider.options.openai.prompt`）として渡します。効くかどうかはまだ分かりません |

**形式で断られたら、WAV に変えて1回だけ送り直します。** 録音の形式（webm）を受け付けない提供元があるためです。

- 断られたら、ブラウザの中で 16kHz・モノラルの WAV に変えて送り直します。
- そのモデルは、以後ずっと WAV で送ります。
- 診断ログの `openrouter-wav-retry` と、設定表の「音声認識(STT)」に出ます。

`openai/gpt-4o-mini-transcribe` など OpenAI の 4o 系は、OpenAI を直接使うときと同じく、次の仕組みが効きます。

- 録音上限
- 末尾繰越（v1.49.32 の息継ぎの対応を含む）
- 結果の順番待ち

## 確認したこと

- `test-hub-stt`（新規・8件）：
  - OpenRouter へは OpenRouter のキーだけを送ること
  - 送る JSON（base64・形式・言語）
  - OpenAI 系だけに用語集を付けること
  - AUTO で言語を送らないこと
  - 形式で断られたら1回だけ WAV で送り直し、以後 WAV にすること
  - それ以外の失敗は送り直さないこと
  - モデル・キーが無いときの案内
  - 4o 系の見分け
  - モデルが空のときに人気1位を入れること
- `test-model-picker-ui`（E2E）11→13件：headless Chromium で、代役の OpenRouter に対して次を確かめた
  - 音声認識に OpenRouter が出ること
  - 一覧が読まれてモデルが入ること
  - 選択画面に文字起こしモデルだけが出ること
  - webm で断られたとき、本物の OfflineAudioContext で 16kHz・モノラルの WAV（0.5秒で 16,044 バイト）に変えて送り直し、文字が返ること

**実際の OpenRouter の音声認識は、まだ確かめていません。** v1.49.34 の接続テストで、音声認識が通るかを先に見てください。
