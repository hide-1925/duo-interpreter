# Duo Interpreter Chrome/Edge 拡張 v1.4.10

HTML v1.48.0 と対で動きます。**v1.4.9 を入れた方は必ずこの版へ入れ替えてください。**

## 1. v1.4.9 の不具合修正（緊急）

**v1.4.9 では popup（拡張のパネル）が開けませんでした。** 「拡張ファイルの版が
一致しません。最新版ZIPを空のフォルダーへ展開し、拡張を読み込み直してください」
が出て、タブ取得・字幕対象の設定・HTML本体への接続がすべて止まります。

原因は v1.4.9 のリリース作業です。popup は service worker が名乗る版を
`manifest.json` と突き合わせ、合わなければ全機能を止めます。

| 場所 | v1.4.9 | 本来 |
| --- | --- | --- |
| `manifest.json` の `version` | `1.4.9` へ更新した | — |
| `service-worker.js` の `workerVersion` | **`1.4.8` のまま残した** | `1.4.9` へ更新すべきだった |

この二重管理は「新しいZIPを古いフォルダへ上書き展開した」状態を検出するための
**意図的な設計**です。service-worker.js だけ古いまま混ざれば検出されます。
意図どおり動いた結果、リリース側のミスを利用者の環境で検出してしまいました。

**同じことが起きないよう、両者の一致を検査するテストを追加しました**
（`tests/test-frame-routing.cjs`）。片方だけ上げると、リリース前にテストが落ちます。

## 2. 版表示が v1.4.0 のままだった不具合

popup の見出しが **v1.4.0 のまま9版ぶん固定**されていました。`popup.html` に
文字列として直接書かれていたためです。

`manifest.json` から実行時に読むようにしました。以後、版表示が実体とずれることは
ありません。ブラウザ名（Chrome / Edge）も実行環境から判定します。
`popup.html` に版を直書きすると落ちるテストも追加しました。

## 3. v1.4.9 で入ったもの（この版でも有効）

**Web Speech API を選ぶと共有音声を認識できなくなっていた不具合**の修正と、
発話の切り出しを秒数ではなく判断で決めるための**計測基盤と判断層の契約**です。
詳細は `history/README-v1.4.9.md` にあります。

**`turnDecisionMode` の既定は `off` で、そのとき境界判定と読み上げ開始は v1.47.1 と
同一の値を返します。** 外部通信も判断層向けの音響計算も発生しません。

## 4. 入れ替え方

1. 最新版 ZIP を**空のフォルダー**へ展開する（古いフォルダーへの上書きは避ける）
2. `chrome://extensions` を開く
3. 既存の Duo Interpreter を**削除**する
4. 「パッケージ化されていない拡張機能を読み込む」で 1 のフォルダーを指定する
5. popup を開き、見出しが **`Chrome v1.4.10`** と出ることを確認する

## 5. 検査

```
NODE_PATH=$(npm root -g) node tests/run-all.cjs --with-e2e
```

| 区分 | 件数 |
| --- | --- |
| 決定論的（`tests/` の11スイート） | 216 |
| `tools/` の3スイート | 46 |
| 実ブラウザ E2E | `test-browser` 成功 / `test-settings-ui` 8 |
| 合計 | **270** |
| 構文検査 | `extension/` の `.js` `.cjs` 40ファイル + `index.html` インラインと `app.js` |

**`tools/` の3スイートを gate に入れました。** 実物の `service-worker.js` や `popup.js` を
読み込むスイートなのに `run-all.cjs` の外にあり、出荷前の検査に入っていませんでした。
入れた直後に、今回の `popup.js` 変更が popup のモック環境で落ちることを検出しています。

内訳は `validation-v1.4.10.json` にあります。版ずれの検査2件は、今回の不具合を
実際に再現させて落ちることを確認済みです。
