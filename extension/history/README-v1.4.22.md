# Duo Interpreter 拡張 v1.4.22

HTML 本体 **v1.49.11**（ビルド `20260923-v14911-aivis-overage-policy`）と対です。

## まず、前版の不具合をお詫びして直しました

いただいたログで **12回**、Aivis で読むはずの発話が `Microsoft Ayumi` に替わっていました。

```
segment tts-rate-fallback {"why":"aivis-window-limit","waitMs":31897,"count60s":10,"limit":10}
```

**原因は前版（v1.49.10）で私が入れた判定です。** 「60秒に10回」という Aivis の公表値を
こちら側で数えて、10回に達したら Aivis に送らずブラウザ内蔵音声へ回していました。

**これが誤りでした。** お客さまのアカウントは**超過分をクレジットで払う設定**になっている
ので、10回を超えても Aivis は受け付けます。**こちら側の数えは「上限」ではなく「予測」
にすぎません。** 予測で送信を止めれば、払う用意のある分まで声が替わります。

### 2つを分けました

|種類|中身|扱い|
|---|---|---|
|**予測**|こちら側で数えた60秒10回|設定で選べる。**既定は止めない**|
|**事実**|Aivis が `429` を返して実際に止めた|**必ず従う**（設定に関係なく）|

⚙ → 音声 → Aivis の「**60秒に10回を超えたとき**」で選べます。

- **そのまま送る**（**既定**）… 超過分は Aivis 側の設定（クレジット消費）に任せます。
  **お客さまの設定ではこれが正しい動きです。**
- **ブラウザ内蔵音声で読む** … 10回を超えた分は Aivis に送りません（前版の動き）。
  課金は増えませんが声が替わります。
- **枠が空くまで待つ** … v1.49.9 以前と同じ。声は替わりませんが**読み上げが数十秒遅れます**。

診断の「Aivis 60秒10回を超えたとき」の行に、いまどの設定か・直近60秒に何回送ったか・
**予測で枠切れなのか Aivis が実際に止めているのか**が出ます。声が替わった理由を後から
追えるようにするためです。

### あわせて、Aivis が本当に 429 を返したときも発話を捨てなくしました

前版まで Aivis の 429 は「時間を置いてカードを再生してください」と出して**その発話を
捨てていました。** 上限以降はブラウザ標準の声で読む、というご指示に合っていません。
OpenAI と同じく**ブラウザ内蔵音声で読み上げます。**

このとき `finish()`（読み上げスロットの解放）は**ブラウザ再生の完了で呼びます。** 先に
呼ぶと次の発話が走り出して**2つの声が重なります。** v1.49.10 で OpenAI 側を直したのと
同じ形に揃えました。

## 「切り方が短すぎる」件 — Jev との比較結果

**Jev は同じログの24回の判定のうち15回、Rules の切り方に反対していました。**
うち10回は confidence 0.70 以上です。**そしてログを読み直すと、Jev のほうが正しいです。**

詳細は `次期仕様実装状況.md` の「v1.49.10 実測ログでの Rules と Jev の比較」に書きました。
要点だけ：

- 25回の確定のうち **13回**が `reason:["stt-final","semantic-final-tail"]`。これは
  **10秒ごとの音声チャンクの終わりで区切られたもの**で、言葉の区切りではありません。
- そのため「In recent years,」／「There appears to have been a」／「crisis of confidence.」
  のように1文が3つに割れ、真ん中が「**があったようです**」という意味を成さない訳文に
  なっていました。**Jev はこの2か所の両方で HOLD（0.85 / 0.88）と言っています。**
- 逆に本当の文末（「That was 40 years ago.」0.98 など）では **9回すべて Rules に同意**
  しています。**当てにならない反対ではありません。**

**この版では Jev の判定を読み上げに使う設定は入れていません。** 入れるかどうかはお客さま
の判断です（`turnDecisionMode=assist` を提案として書いてあります）。判断層が黙って
切り方を変えると、**今まで追ってきた比較の土台が崩れます。**

## 変えていない約束

- 判断層（Jev）を off にすれば v1.47.1 と同じ挙動に戻ります（INV-08）
- 判断用の API キーは翻訳キーから流用せず、設定埋込み HTML にも入りません
- 会議の生テキストは `turnDecisionRawLog` を明示的に入れない限りログに残りません

## テスト

**決定的 380 件 + E2E 13 件 = 393 件 全通過。**
`test-tts-limits` を 17 件から 27 件へ増やしました。検査したのは次の点です。

- 既定（そのまま送る）では、予測で枠を使い切っても**送信を止めないこと**
- Aivis が 429 を返したときは、**どの設定でも**止まること
- 予測が**サーバの停止時間を短くできない**こと（60秒の予測が2分の 429 を打ち消さない）
- 「枠が空くまで待つ」が v1.49.9 以前と同じ動きに戻ること
- 壊れた設定値（空・未知の文字列）が **`send` として読まれる**こと
  （ここを誤ると、払う用意のあるアカウントで声が替わり続けます）
- 画面に出している3つの選択肢が、**コードが理解する3つと一致していること**
