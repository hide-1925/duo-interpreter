# Duo Interpreter 拡張 v1.4.3

HTML本体はv1.47.0のまま使用できます。

## 更新

1. ZIPを解凍し、中身を現在の拡張フォルダーに上書きします（manifest.jsonを同じ階層に配置）。
2. Chromeの拡張機能管理画面でDuoを再読み込みし、1.4.3であることを確認します。
3. TeamsとDuo本体のページを再読み込みし、会議へ入り直します。
4. 通常どおりDuoを開始し、「web会議マイク音声」をONにします。

## v1.4.2でも接続できなかった理由

最新ログでは、マイク取得1件、接続済み通信1件、音声送信1本、画面共有0件が確認できました。しかし、MediaStreamAudioSourceNodeからMediaStreamAudioDestinationNodeに渡す音声が「externalEvidence:true」と分類され、接続候補から除外されていました。
v1.4.2には「マイク由来だと証明できない」と「外部音声だと観測できた」を混同する判定が残っていました。これはアドオン側の実装不備です。ユーザーの設定変更では解消しません。

## 修正

- 出所不明のストリームは出所不明として扱い、外部音声の証拠にはしません。
- Teamsの受信イベントと受信トラック一覧から、実際に受信した相手音声を識別します。画面共有トラックも取得時に識別します。
- この識別を複製・加工の上流までたどり、実際の受信音声や画面共有を含む経路は除外します。
- 接続済み通信の音声送信が1本、マイク取得元が1系統、画面共有なし、外部音声の証拠なしという条件を満たす加工音声を、明示的な接続ボタン操作の対象として選びます。これは送信先の一意性による推定であり、マイク由来の完全な証明ではありません。
- 診断にはsourceReasonsを追加し、unobserved-origin、remote-receiver、display-capture等を区別します。音声や会話本文を新たに保存・送信しません。

前版の50ミリ秒フェードインによるタブ再生開始時の音量切替対策は維持しています。

## 検証範囲

今回提供されたログから、個人識別情報や接続トークンを含まないdiscovery部分をテスト条件に使用しました。
取得数・送信数・複製数・ノード構成を合わせた模擬環境で、旧判定による同じ拒否を再現した後、新判定による接続、ミュート維持、解除時の元音声への復帰を確認しました。相手音声・画面共有の識別も別の再現テストで確認しています。
Node VMの再現・回帰テスト106件と31ファイルの構文チェックが成功しています。詳細はvalidation-v1.4.3.jsonを参照してください。
実際の企業Teamsでの音声到達は未確認です。模擬テスト成功を実環境での成功と同一視していません。ブラウザーを取得できない作業環境のため、同梱の実ブラウザ検証スクリプトも未実行です。
