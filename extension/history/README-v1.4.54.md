# Duo Interpreter 拡張 v1.4.54

HTML 本体 **v1.53.0**（ビルド `20260930-v1530-stt-credential-routes`）と対です。

`STTマルチプロバイダ開発仕様書.md` §8.3・§8.4 の**一時キーの発行経路**です。これで Phase 5 のコードが揃いました。
**既定は今までどおり「直接」で、そのままなら v1.52.0 と同じ動きです。**

## 1. 足したもの

| | 内容 |
|---|---|
| 設定 | ⚙→音声→ストリーミング認識の設定に「一時キーの発行」（直接（既定）／拡張が中継／Token Broker）。Token Broker のときだけ URL の欄が出る |
| 拡張が中継（relay） | 新しい `stt-relay.js`。拡張の service worker が ElevenLabs・AssemblyAI・Soniox の**固定の発行元へ、一時キーの発行だけ**を中継する。HTML 版（GitHub Pages）で発行元が CORS を許さない会社向け |
| relay の縛り | ページが渡せるのは会社名とキーだけ（URL・ヘッダ・本文は拡張の表で決まる）。頼めるのは拡張の画面と登録済みの HTML本体のタブだけ。Cookie を送らない。キーと応答を記録しない。OpenAI は中継しない（ブラウザから発行でき、SDP の交換も直接のため） |
| 古い拡張への対応 | 内容スクリプトが中継に対応していることを名乗る。対応していない拡張・つながっていないタブでは、中継を頼まずに理由を出して止める |
| Token Broker（broker） | `POST {URL}/token/stt/{会社}`、本文 `{"model":…}`（gpt-live は session も）→ `{"token":…}`。ページに各社のキーは要らない。Cookie を送らない。応答の本文を文言と記録に入れない。URL は HTTPS で、認証情報・クエリ・フラグメントを含むものは保存しない。診断はオリジンだけ |
| 🔍 確認 | 選んでいる経路で一時キーの発行を試す（中継・Broker が通るかも分かる） |
| 診断 | 「一時キーの発行経路」の行（direct／relay と拡張の接続状態／broker とオリジン）。発行の記録に `route` |

どの経路でも、**音声はこのページから各社へ直接**送り、WebSocket に使うのは一時キーだけです。拡張の権限は増えていません。

## 2. 変えていないこと

- 直接（既定）のときの要求・文言・記録（`test-stt-keys`・`test-stt-live-parity` はそのまま通る）。
- 判断層の中継（`turn-proxy.js`）の縛り。中継の返事の通り道（`duo-turn-reply`）を共有するだけ。

## 3. 検査

- `test-stt-relay`（新規・22件）… 拡張の側：固定の発行元・ヘッダ・本文、ページの URL などを使わない、表に無い会社（OpenAI・`__proto__` など）を断る、
  拡張の画面と登録済みのタブ以外を断る、キーの形、状態をそのまま返す、通信断・時間切れ・大きすぎる応答、記録しない。
  表が直接の要求と同じこと。内容スクリプトが会社名とキーだけを渡すこと。ページの側：relay と broker の成功・文言・分類、
  拡張が無い・古いとき、OpenAI は direct、Broker の URL の検査、gpt-live の Broker、既定は直接。
  拡張の縛りなど7か所を1つずつ外すと、それぞれこの検査が落ちることを確かめた。
- `test-stt-stream-ui`（実ブラウザ・11件）… relay で拡張の代わりが返した一時キーで AssemblyAI へ、broker で Soniox のキー無しに接続して音声が流れる。
- `test-stt-settings-ui`（実ブラウザ・15件）… 経路のプルダウン、Broker の URL の欄の出し入れと検査、診断はオリジンだけ。
- `test-stt-live-host`（31件）… broker なら、キーの無い予備も自動フォールバックで飛ばさない。
