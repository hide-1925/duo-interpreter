# Duo Interpreter 拡張 v1.4.29

HTML 本体 **v1.49.18**（ビルド `20260924-v14918-src-font-ratio`）と対です。

## 1. 原文の大きさを、訳文比の％で決められるようにしました

⚙ → 表示・記録 → 表示 → **原文サイズ**（40〜100%・5%刻み・**既定 60%**）

これまで**面ごとに違う値が直書き**されていました。設定はどこにもありませんでした。

|字幕の出る場所|変更前|変更後|
|---|---|---|
|HTML本体の会話バブル|**50%** 固定|`原文サイズ`（既定 **60%**）|
|タブ内の字幕オーバーレイ|**58%** 固定|同じ設定を見る|
|別ウィンドウ／PiP の字幕|**65%** 固定|同じ設定を見る|

3面とも `--src-ratio`（本体・PiP）と `--duo-sub-ratio`（タブ内）という1つの比を読みます。
比なので、**文字サイズを変えても原文と訳文の比は変わりません**。

- 本体とPiPは即座に反映します。
- タブ内オーバーレイは `DUO_PROFILE` で送るため、**拡張が読み込まれているときだけ**追随します。

## 2. Jev 経路の既定 model を固定version にしました

**これは実機ログで見つかった不具合です。** `active` で1本会議をしても、判断層は
**一度も動いていませんでした**。

```
判断層の往復 | 送信 13 / 正常応答 0 / 適用 0
判断の内訳   | 確定 rules 85 / provider 0
turn-circuit-open {"reason":"active では model に固定versionを指定してください（いまは jev-latest…）"}
```

`assist` 以上では alias（`jev-latest` / `jev-preview`）を拒否する仕様は正しいのですが、
**経路の既定が `jev-latest`** だったため、model 欄を空のまま `active` にすると
**送信のたびに自分で拒否して Rules へ落ちる**状態になっていました。circuit breaker は
設計どおり働き、訂正率も 0.0% のまま——**つまり「Jev を試した」結果ではありません**。

|項目|変更前|変更後|
|---|---|---|
|経路の既定 model|`jev-latest`（alias）|**`jev-1.13.0`**（固定version）|
|拒否の対象|assist／active（メッセージは「active では」）|assist／active（**メッセージも「assist／active では」**）|
|自分で alias を入れたとき|診断ログにだけ理由が出る|**状態行に「⚠ …alias なので送信は毎回拒否されます」**|

`shadow` は動作へ反映しないので、自分で alias を入れたならそのまま送ります。

## 3. 「読み上げが始まらなかった」を追えるようにしました

同じログで、1枚だけ `tts_generating` のまま `audio cancelled` になったカードがありました。
**原因は `segCancelAudio` が残す `audio-cancel {why}` に必ず出ます**が、その行は
**保持件数の外に落ちていました**（記録件数 846＝上限）。

|項目|変更前|変更後|
|---|---|---|
|行動ログの保持|**800件**（7分の会議で最初の6分が消える）|**3000件**|
|`audio-start` の記録|`DLOG.push` 直書き（**上限を無視**していた）|`dlog()` 経由|
|診断のカード行|`audio cancelled`|`audio cancelled（**理由**）`|

理由はそのまま出ます — `conference-off` / `speech-stopped` / `echo` /
`source-or-translation-updated` / `translation-error` / `not-selected-or-empty` /
`floor-expired` / `backchannel`。`segCancelAudio` を呼ぶのは「読み上げON/OFF」
「TTS方式を変更」「逐次読み上げ設定変更」「別の文を読み上げ」「会話ログを消去」
「認識停止」など**操作**です。次に起きたら、この1行で分かります。
