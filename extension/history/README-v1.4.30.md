## Jev は動いていましたが、答えが毎回「一手遅れ」でした

v1.49.18 で `active` の実機ログが取れました。**接続は完全に正常**です。

```
判断層の往復 | 送信 51 / 正常応答 51 / 解析失敗 0 / 到達不能 0 / 適用 0
判断の内訳   | 確定 rules 77 / provider 0
```

**51回聞いて51回答えが返り、採用は0回。** 原因はログの時刻に出ています。

```
[+246.163s] turn-decision-request  candidates 3
[+246.163s] commit seq=1 / seq=2 / seq=3      ← 同じミリ秒で Rules が3つに切った
[+246.355s] turn-decision-result   choice C_STABLE_159   ← 192ms後「切らず159文字で1つ」
```

質問は **commit と同じ tick** で飛びます。答えは 174〜483ms（中央値およそ205ms）で
返りますが、そのときには Rules が切り終えていて、答えを渡す相手がもう居ません。

録音分割REST（`gpt-4o-mini-transcribe`）では**確定した文が一度に届く**ため、
文字が伸びていく途中の局面がありません。つまり **この経路では active は構造的に
空回りします。** Jev の問題でも設定の問題でもなく、こちら側の設計の穴です。

### 直したこと — 有界の待ち（INV-10）

⚙ → 音声 → 発話交代の判断層 → **確定を待つ上限 ms（0＝待たない）**（既定 **300ms**、上限1000ms）

- 待つのは **「いま投げた、この文の答え」だけ**。別の文の答えや、そもそも投げていない
  ときは待ちません（`inflight` の鍵が一致する場合のみ）。
- 上限を過ぎたら **Rules が確定します**。答えが来なくても止まりません。
- **`off` と `shadow` は一切待ちません**（INV-08 はそのまま）。
- 読み上げは元から数秒〜数十秒遅れて進みます（このログでは `L2CommitProxyMs` が
  1.6〜22.2秒、`debtEstimateSeconds` が最大30.8秒）。**0.3秒の追加は耳では分かりません。**

`0` にすれば v1.49.18 と同じ挙動に戻せます。

## Jev が実際に言っていたこと（51件）

|Jev の答え|件数|内容|
|---|---:|---|
|Rules に同意|32|同じ位置で切れ|
|**もっと後ろで切れ**|14|1枚のカードを2〜5個に割ったのを「割らず1つに」|
|**HOLD（待て）**|5|文の途中なので切るな|
|もっと前で切れ|**0**||

**3回のログ・約100件の判断を通じて、Jev が「もっと早く切れ」と言ったことは一度もありません。**

「後ろで切れ」14件が、そのまま**「切り方が短すぎる」**の正体です。例えば1枚のカードで

- Rules: `45 / 33 / 96 / 39 / 107` 文字の5分割 → Jev:「320文字で1つ」
- Rules: `72 / 43 / 6 / 84` 文字の4分割（`ゼロです。`が単独）→ Jev:「205文字で1つ」

HOLD 5件は**カードをまたぐ**同じ問題です。30秒の録音区切りが文の途中に落ちるため、

> `…on this continent,` ／ `I can report to you with pride that...` ／ `America is back...`

が3枚のカードになり、日本語も3文に割れて読まれます。Jev は前2つを HOLD（0.9）と
判定しています。**こちらはカードをまたぐ結合が要るので、今回は直していません。**

## 読み上げが止まったカードの理由を出すようにしました

v1.49.18 で「カード行に理由を併記する」を入れましたが、**いちばん多い経路が漏れて
いました**。`segCancelAudio`（読み上げOFF・設定変更・別の文を再生・認識停止など）は
`skipReason` を残していなかったため、今回のログでも最後のカードが理由なしの
`audio cancelled` になっています（実際は `+601.941s audio-cancel {"why":"認識停止"}`、
つまり停止ボタンです）。ここで `why` を残すようにしました。

## テスト

**決定的 443 件 + E2E 13 件 = 456 件 全通過。**

`test-turn-decision` に7件追加（62→69）。待つ相手と上限を縛ります。

- rules 経路では何も飛んでいないので `active` でも待たないこと

- **`off` と `shadow` は往復が飛んでいても待たない**こと（INV-08）
- 答えが届いた次の tick で、その答えが採用されること
