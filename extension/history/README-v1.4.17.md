# Duo Interpreter 拡張 v1.4.17

HTML 本体 **v1.49.6**（ビルド `20260923-v1496-tail-card-span`）と対です。

## この版でやったこと

**繰越した末尾カードが、元の発話開始時刻を引き継いでいました。**

いただいた v1.49.5 の実機ログで気づきました。カード e1・e2・e4・e6・e8 の
`startedAt` が**全部同じ値**（`1790097366503`）で、`endedAt` だけが10秒ずつ進んで
います。話し続けている40秒が、まるごと1枚のカードの区間として扱われていました。

`gpt-4o-mini-transcribe` は10秒で録音を切り、文末までの分を確定して残りを次へ繰越
します。その繰越カードを作るとき `tail.startedAt = e.startedAt` としていたため、
**話し続けている間ずっと最初の発話開始時刻に固定**され、録音ごとに区間が伸びました。

### 害は3つあります

**1. 話者帰属が誤ります（いちばん重い）**

`duoSpeakerResolve` は `[startedAt, endedAt]` の窓で話者タイムラインと重なりを取り、
**いちばん長く重なった人を選びます。** 窓が40秒に広がると、末尾カードが受け持つのは
最後の数秒なのに、**それより前に長く話していた別人が選ばれます。**

「複数話者」で判定不能になるのではなく、**静かに間違った名前が付く**ほうが厄介です。
検査でその形を再現しました（p1 が30秒、p2 が8秒話したあとの末尾カードは p2 のもの
ですが、広い窓では p1 が選ばれます）。

Teams の話者帰属精度は Phase 0 の未測定項目なので、**測る前にこれを直す必要が
ありました。** このまま測れば、実装のバグを精度として記録するところでした。

**2. 再開後の自動読み上げから外れうる**

`duoAutomaticAllowed` は `startedAt > resumeAfter` で判定します。再開後に生まれた
末尾カードが古い時刻を持つと「再開前のもの」と見なされ、自動読み上げが止まります。

**3. `L1TextProxyMs` が遅延を表さなくなる**

`firstAudioAt - startedAt` なので、遅延ではなく**「話し始めてからの経過時間」**に
なります。実機ログでは 12.6 → 22.9 → 32.0 → **43.5秒** と、10秒ずつ際限なく伸びて
いました。**私はこの数字を一度latencyとして読み、危うく誤診するところでした。**

### 直し方

`startedAt` と対になるのは `audioEndedAt`（録音の meta から入る組）なので、繰越
カードの開始はそこから取ります。`fourOTailStart()` に切り出して単体で検査できる
形にしました。無いときは従来どおりに落とします（`endedAt` → `startedAt`）。

## 実機ログから読み取れた実測値（v1.49.5）

L1 が壊れていたので、残りの2つで読みます。**待ち行列は問題ありませんでした。**

|指標|実測|評価|
|---|---|---|
|`L2CommitProxyMs`|**0.46 / 0.80 / 0.90 / 2.38 秒**|commit から音が鳴るまで。**良好**|
|`L3Ms`|5.9 / 10.6 / 11.5 秒|発話終了から読み上げ終了まで|
|Aivis 残リクエスト|**6 / 10**|前回は0。**余裕あり**|

前回のログ（v1.49.2）で見えた「5文字以下の相づちが待ち行列と Aivis 枠を食う」現象は
**今回は起きていません。** 連続した語りなので1回の確定が 55〜145文字とまとまり、
4回の合成で済んでいます。**待ち行列も Aivis も詰まっていません。**

残る遅れは**10秒の録音窓そのもの**です。今回のログは録音の切り方が**すべて
`reason:"limit"`（10秒上限）**で、`silence` による早い切り上げが一度も起きていません。
話が途切れないので必ず10秒待ってから送ることになり、**文字が出るのは音声の10秒窓が
終わってから約1〜1.8秒**です。

これは `gpt-4o-mini-transcribe` の録音分割REST方式に由来するもので、**判断層でも
待ち行列でも直りません。** ストリーミングSTT（`gpt-live-transcribe`）に替えると
この10秒が消えます。以前そうされていたときは L3 の中央値が約2.4秒でした。
