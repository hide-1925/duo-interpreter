# Duo Interpreter Chrome/Edge 拡張 v1.4.11

**HTML v1.49.0 と対で動きます。**

## 1. この版でやったこと

中身は v1.4.10 とほぼ同じで、**版の名乗りを正すための版**です。

HTML 側に判断層の経路レジストリ・経路選択とAPIキーのUI・診断ログを入れたとき、
`APP_VERSION` を `v1.48.0` のまま据え置いてしまいました。結果、**中身の違う2つの
ビルドが同じ `v1.48.0`・同じビルドIDを名乗る**状態になりました。

| コミット | 名乗り | index.html の実体 (SHA-256 先頭) |
| --- | --- | --- |
| `454a232`（リリース済み） | `v1.48.0` | `4e16d461…` |
| `1bdeb9b` | `v1.48.0` | **`d689c7fc…`** ← 別物 |

診断ログの版とビルドIDだけでは見分けられません。`v1.49.0` として名乗り直しました。

拡張の zip には `app.js` が入るため、HTML の版が変われば**拡張パッケージの中身も変わります**。
だから拡張も `1.4.11` へ上げます。対になる版は `versions.json` に記録します。

## 2. 再発を止める仕組み

`tests/test-release-manifest.cjs` を追加し、gate に入れました。規則はひとつです。

> いま名乗っている版が `versions.json` に記録されているなら、
> 記録された SHA-256 と実ファイルが一致しなければならない。

中身を変えたら版を上げるしかなくなります。あわせて次も検査します。

- `APP_BUILD` が版の名前を含むこと（版だけ上げてビルドIDを据え置く取り違えを止める）
- `manifest.json` の版が、その HTML 版と対になっている版であること
- その拡張版の `README-v*.md` が存在し、対になる HTML 版を明記していること
- 2つの版が同じ `index.html` を記録していないこと（どちらかが誤記である証拠）
- `commit` を記録した版は、実際に git のその地点の中身と一致すること

過去の版のハッシュは**手書きではなく git から実測**しました。手で書くと、まさに
今回の取り違えが記録側で再発します。

## 3. v1.4.10 / v1.4.9 で入ったもの（この版でも有効）

- **v1.4.10** — v1.4.9 で popup が開けなくなっていた不具合の修正
- **v1.4.9** — Web Speech API で共有音声を認識できなかった不具合の修正と、判断層の計測基盤

詳細は `history/README-v1.4.10.md` と `history/README-v1.4.9.md` にあります。

**`turnDecisionMode` の既定は `off` で、そのとき境界判定と読み上げ開始は v1.47.1 と
同一の値を返します。**

## 4. 入れ替え方

1. 最新版 ZIP を**空のフォルダー**へ展開する（古いフォルダーへの上書きは避ける）
2. `chrome://extensions` で既存の Duo Interpreter を**削除**する
3. 「パッケージ化されていない拡張機能を読み込む」で 1 のフォルダーを指定する
4. popup の見出しが **`Chrome v1.4.11`** と出ることを確認する
