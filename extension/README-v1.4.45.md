## 翻訳モデルを「おすすめ」か「作った会社」から選ぶ

翻訳プロバイダが OpenRouter か Groq のとき、翻訳モデルの横に「🔎 選ぶ」が出ます。

- **おすすめ**：速さ・精度・安さ・人気の4つの型で、上位3件を出します。
  - OpenRouter は、モデル一覧の並べ替え（`sort`）と用途「translation」の絞り込みを OpenRouter 側に任せます。
  - 行ごとに、価格（100万トークンあたり）、印（無料・推論あり・提供終了予定日）、直近30分の応答の速さ（提供元のうちいちばん速い中央値）を出します。
  - Groq の一覧には速さ・性能の情報が無いので、内蔵の候補のうち、そのアカウントで使えるものだけを出します。
- **全部から選ぶ**：作った会社（件数つき）→ その会社のモデル（新しい順）の2段です。
  - 名前・ID で探せます。探すときは会社をまたぎます。
  - 「無料だけ」「データを残さない先があるものだけ」で絞れます（後者は OpenRouter のみ）。
- **試しに使う**：選んだモデルで見本の1文を訳し、かかった時間を出します。
- スマートフォンの幅では全面に出ます。Esc で閉じ、「🔎 選ぶ」へ戻ります。

一覧は機能ごとに取り、24時間ブラウザに置きます。OpenRouter の一覧はキー無しで取れるので、キーを入れる前からおすすめを出せます。

## OpenRouter の翻訳の直し

| 直したこと | 前 | 今 |
|---|---|---|
| キーの確認 | キー無しでも返る一覧（`GET /models`）で見ていたので、間違ったキーでも「接続できました」になった | `GET /key` で確かめる。無料枠かどうかと残りの上限も出す |
| 推論 | 推論モデルも考えてから訳していた | 推論を切る（`reasoning.effort: none`）。切れないモデルは、選べるうちいちばん弱く |
| temperature | 必ず送っていた | 受け付けるモデルにだけ送る |
| 提供元の選び方 | OpenRouter 任せ | 「速さ優先」（`provider.sort: latency`、既定）／「安さ優先」／「OpenRouter に任せる」 |
| データの扱い | 指定なし | 「データを残さない提供元だけ使う」を ON にすると、`provider.zdr` と `data_collection: deny` を付ける（既定 OFF） |
| 内蔵の一覧 | 7件・古い | 先頭を `deepseek/deepseek-v4.1-flash` と `google/gemini-3.8-flash` に。取得した一覧が優先 |
| カメラ翻訳 | `gpt-4o-mini` をそのまま送っていた | OpenRouter では `openai/gpt-4o-mini` の形にする |
| 議事録 | 出典ヘッダ無し | 翻訳と同じヘッダと推論の指定を付ける |

診断の設定表に「OpenRouter」の行を足しました。キーの長さ、提供元の選び方、データの扱い、最後に翻訳した提供元、接続テストの結果が出ます。キーの中身は出しません。

出典ヘッダは、今までどおり `HTTP-Referer` と `X-Title` だけです。公式 SDK は `X-OpenRouter-Title` を使いますが、ブラウザから呼ぶので、ヘッダを増やすと事前確認（CORS）で断られるおそれがあります。

## Groq の翻訳の直し

- gpt-oss は推論を弱く（`reasoning_effort: low`）します。
- Qwen3 は推論を切ります（`reasoning_effort: none`）。
- 考えた過程は本文に混ぜません（`reasoning_format: hidden`）。
- どのプロバイダでも、返った文に `<think>…</think>` が混ざっていたら取り除きます。
- 一覧は名前で分けます。whisper は音声認識、orpheus・tts は読み上げ、guard は使わないので、翻訳の一覧には出しません。

## ① 接続テスト

OpenRouter を選ぶと「接続テスト」が出ます。次の4つを1つずつ小さく送り、ブラウザから直接呼べるかを確かめます（少額の料金がかかります）。

1. キー（`GET /key`）
2. 翻訳（`/chat/completions`、8トークンまで）
3. 読み上げ（`/audio/speech`、「テスト」の3文字）
4. 音声認識（`/audio/transcriptions`、0.6秒の無音）

通信できなかったときは「ブラウザから呼べませんでした（CORS か通信）」と出ます。読み上げでは、返ってきた形式（`content-type`）とバイト数も出します。

**③ 読み上げと ④ 音声認識は、このテストの 3・4 が通ることを確かめてから入れます。** お手数ですが、実際のキーで一度押して、結果（診断ログの `openrouter-test`）を教えてください。

## 確認したこと

- `test-model-hub`（新規・12件）：
  - 一覧を機能ごとに `output_modalities` で、キー無しで取ること
  - 24時間置くこと
  - おすすめの並べ方
  - Groq の名前での振り分け
  - 推論・temperature・提供元・データの扱いの付け方
  - `<think>` を取り除くこと
  - キー確認が `GET /key` を使うこと
  - 接続テストが1つずつ進み、通信できないときにそう書くこと
  - 速さの読み取り
- `test-model-picker-ui`（新規・E2E・8件）：headless Chromium で、代役の OpenRouter に対して次を確かめた
  - おすすめ → 型の切り替え → 作った会社 → 絞り込み・検索 → 試す → 決める
  - スマートフォンの幅
  - Esc

**実際の OpenRouter・Groq では、まだ確かめていません。** 特に、応答の速さの数値の単位（ms か秒か）は資料で確かめられていません。20以上なら ms とみなしています。
