# Duo Interpreter 拡張 v1.4.19

HTML 本体 **v1.49.8**（ビルド `20260923-v1498-tail-window-share`）と対です。

## Jev が Rules より良い判断をした実例が出ました

v1.49.7 の実機ログ（英語→日本語、翻訳あり）で、**10回中9回は Rules と一致し、1回だけ
不一致**でした。その1回が重要です。

```
e9: choice "HOLD"
    probabilities {HOLD: 0.52, C_RULES_159: 0.48}
    confidence 0.04   safeToSpeak 0.84
```

対象の文：

> and implementing the programs of actions for least developed countries, landlocked
> developing countries, and small island developing states, as well as Africa.

Rules はここで切りました。**その結果、次のカードが「units, Agenda 2063.」だけになり、
「ユニット、アジェンダ 2063。」という意味を成さない断片が読み上げられました。**

実際の発話は "...as well as Africa['s] Agenda 2063" のように続いていたはずで、
**e9 は文として終わっていませんでした。Jev の HOLD が正解です。**

ただし `confidence 0.04`（0.52 対 0.48）で、**ほぼ五分五分の判断**です。どの閾値でも
通りません。**方向は正しいが、確信は無い**という状態です。これが校正すべき対象です。

## この版で直したこと — 私の前々版の取りこぼし

**v1.49.6 で入れた繰越カードの修正に、片方の場合が抜けていました。**

v1.49.6 では繰越カードの開始を「直前のカードの音声の終わり（`audioEndedAt`）」にしました。
次の録音を取り込めば終わりも進むので問題は出ません。**ところが無音で解放されると
終わりが進みません。** 実機ログの e7 がそれで、`startedAt` と `endedAt` が同値
（`1790107404014`）、**区間が0秒**になっていました。

`duoSpeakerResolve` は `end=max(start+1,end)` で潰れないようにしているだけなので、
帰属は **confidence 0.2 の low** に落ちます。**誤った名前が付いていた元のバグより害は
小さいですが、正しくもありません。**

### 直し方

繰越カードの音声は、その録音窓の**中**にあります。文字数の比で窓の終わりから手前へ
戻します。

e7 の例：窓は 10,021ms、確定38字・末尾93字。末尾は約71%なので、**始まりは終わりから
約7.1秒手前**。区間は約7.1秒になります。

話速は発話内で変わるので**概算です。**ただし区間が潰れることも、話し続けるほど伸びる
こともありません。どちらも実測ログで起きた失敗です。

## 実測値 — 遅延がかなり改善しています

|指標|v1.49.5（連続した語り）|v1.49.7（自然な間のある演説）|
|---|---|---|
|`L2CommitProxyMs` 中央値|約6.2秒 → 0.5〜2.4秒|**約1.3秒**|
|`L3Ms` 中央値|約9.1秒|**約4.2秒**|
|10秒上限で切れた録音|**全部**|**11回中3回だけ**|

**原因が確認できました。** 今回は自然な間があるので `4o-recording-cut` が
`reason:"silence"`（1.7〜8.3秒）で早く切り上がり、10秒待つ必要がありません。

**「10秒の録音窓は、話が途切れないときだけ効いてくる」**という前版の分析が裏づけられ
ました。演説や会話なら現状のままでも 4秒台です。

## 注意が必要なもの

**Aivis の残リクエストが 1/10 になりました。** 翻訳が入ると1発話につき1リクエストなので、
50秒で9回使っています。**実際の会議では上限に当たって待たされます。** 上限は
60秒あたり10回です。

翻訳は `free` で、途中で `free-google-FAIL {"err":"google 500"}` から mymemory へ
自動で切り替わっています（結果は妥当でした）。**この経路は動いていますが、
無料枠なので品質と可用性は保証されません。**
