# Duo Interpreter 拡張 v1.4.38

HTML 本体 **v1.49.27**（ビルド `20260926-v14927-webspeech-60s-join`）と対です。

## 文の途中で会話カードが割れていた件

v1.49.26 の記録では、カード e1〜e3 がすべて**ちょうど約60秒**で切れていました
（59.3秒・60.0秒・60.1秒）。

```
e1 の最後  …公式ドキュメントではどちらも、マニュアル、つまり、全ての操作を。
e2 の最初  確認するモード、で始まると書かれています。
e2 の最後  …管理、設定は組織の IT 担当が。
e3 の最初  全員に強制する、設定、なのだ。
```

Chrome の Web Speech は、話し続けていても**約60秒で結果を強制的に確定**させます。
その位置は文の途中でも構いません。Duo は確定のたびにカードを閉じていたので、文の途中で
カードが割れていました。閉じた側には、実際には無い「。」まで付いていました。

### 直したこと

- 確定した本文が**文末で終わっていないとき**は、すぐにはカードを閉じずに **1.5秒** 待ちます。
  次の結果が来たら、同じカードへつなぎます。
  - 文末で終わっていないとは：「〜を」「〜が」「〜で」のような続きの形、または語尾から文末と言えない形。
  - カードが始まって50秒を過ぎていれば、語尾に関わらず待ちます（60秒の打切りが「〜です」の直後に来ることもあるため）。
- 1.5秒たっても次が来なければ、そのまま閉じます。「。」を付けるのはこのときだけです。
- 「です」「ます」などで終わっていれば、従来どおりすぐに閉じます。

実ブラウザで、記録と同じ位置（「…全ての操作を」）で強制確定を起こしました。
旧版は2枚に割れて「全ての操作を。」になり、新版は1枚のまま
「…全ての操作を確認するモード、で始まると書かれています。」とつながりました。

## 同じ記録で見つかった、読み上げの待ち（8.2秒・3.3秒・8.4秒）

「…確認できたのは2件だけです」のように**語尾で文末と判定して確定した部分**は、
確定した時点ではまだ「。」がありません。次の結果で空白が「。」になりますが、その「。」は
**次の部分の先頭**に入ります（「。他はチェンジ…」）。

Aivis へは文の終わりで区切って渡すため、読み上げは「。」で終わる部分が来るまで待ちます。
そのため、次の文が確定するまで止まっていました。

```
e1-s4  …2件だけです      → 読み上げ待ち 8,233ms
e1-s11 …切った環境です    → 読み上げ待ち 3,287ms
e2-s2  …説明のままです    → 読み上げ待ち 8,402ms
```

次の2つも「文の終わり」として扱うようにしました。

- Rules が語尾で文末と判定して確定した部分（`semantic-ending`）
- 後ろの本文が「。」「？」で始まっている部分

## 判断層（Jev）について、この記録から分かったこと

| 項目 | 値 |
|---|---|
| 送信 | 383件（約190秒、毎秒約2回） |
| 1回の入力 | 約1,200〜3,000トークン |
| Jev が確定した部分 | **0件**（40件すべて Rules） |

Jev は息継ぎの候補にほとんど確信を持てていません。「。で終わる」の確率は最大でも0.44で、
採用の下限0.8に届きませんでした。多くは HOLD（待て）でした。ただ、HOLD の間 Rules 側にも
確定できるものが無かったので、確定を遅らせたのは最後の1件（約0.7秒）だけでした。

**速くも遅くもならず、費用だけがかかっている状態**です。Web Speech の日本語では、
判断層を shadow（記録だけ取る）か off にしておくことをお勧めします。

## 確かめたこと・確かめていないこと

- 実ブラウザで、60秒の強制確定を文の途中で起こし、1枚につながることを確かめました。
- 読み上げの待ちは試験で固定しましたが、Aivis を使った実機ではまだ確かめていません。
- 1.5秒の待ちは、記録で Chrome が次の結果を出すまでの時間（34〜170ms）から決めました。
  本当に話が途切れたときは、最後の部分の確定がこの分だけ遅れます。
