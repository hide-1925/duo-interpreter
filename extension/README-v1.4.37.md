# Duo Interpreter 拡張 v1.4.37

HTML 本体 **v1.49.26**（ビルド `20260926-v14926-webspeech-breaths`）と対です。

v1.49.25 の記録（Web Speech＋Jev active、約60秒の会話動画）から、次の4つを直しました。

## ① 直接開いた HTML 本体も、アドオンに自動で接続する

Jev の「アドオン経由」は、アドオンに登録された HTML 本体のタブからしか中継を頼めません。
これまでは、ポップアップの「HTML本体を開く」か「このタブに字幕表示」を押したときだけ
登録していました。そのため、**ブックマークや URL 直打ちで開いた HTML 本体は未接続**のまま
でした。記録では送信3件がすべて「HTML本体がアドオンに接続されていません」で失敗し、
8.4秒で判断層が止まっていました。

- 登録した URL のページが読み込み終わったら、自動で接続します。
  **字幕表示を押す必要はありません。**
- すでに接続中の HTML 本体タブが別にあるときは、それを奪いません。
- 接続するだけで、認識は始めません。
- 字幕対象が無いときは、タブ音声の経路は作りません。以前は、字幕対象のタブを閉じたあとに
  HTML 本体を接続し直すと「先に字幕対象と…」のエラーで終わる経路がありました（コード上の確認で、
  実機では再現させていません）。

**反映には拡張の更新が必要です**（HTML だけの差し替えでは効きません）。

## ② Chrome が2つに分けて返す途中結果を、1枚のカードにする

Chrome は途中結果を「安定した前半」と「揺れる末尾」の2つに分けて返します。Duo はそれを
別々のカード（e1 と e2）にしていました。最新の数語は e2 に入るため、e1 の文末
（「…ことだよね」）の後ろに次の語が来るまで「。」が付きませんでした。

```
v1.49.25  「…ことだよね」が見えてから確定まで 約4.7秒
          約60秒で打ち切られた前半が語の途中で確定し「…協力を得られ。」
          ＋ 別カード「れば、作り上げられるという発想だな」
```

- まだ閉じていない途中結果を、先頭から全部つないで1枚にします。すべて確定したら閉じます。
- 途中の確定境界でカードを閉じるのは、境界が文末で、そこまでが過不足なく確定済みのときだけです
  （確定済みの部分を削らないため）。
- 実ブラウザで、末尾6文字を別の結果にした途中結果を流しました。1文目が確定するまでの
  時間は **981ms → 537ms** になり、取り残されるカードも出なくなりました。実際の記録では
  末尾が最大23文字あったので、差はもっと大きくなるはずです。

## ③ 息継ぎの位置を、判断層（Jev）の切り所の候補にする

語尾の規則は、話し言葉の文末（「〜んじゃないの」「〜だぜ」「〜っけ」「〜でな」）を拾えません。
記録では **112字の長さ打切りが2回**起き、1回は「、」で終わったため、読み上げがさらに
**4.7秒**待ちました。そのうえ「作れちゃうんじゃないの」「大丈夫なの」「断ったんじゃなかったっけ」は
疑問文なのに、平叙のまま読まれていました。

- Web Speech のカードでは、空白を直した「、」の位置を切り所の候補として Jev に渡します。
  1か所につき「**。で終わる**」「**？で終わる**」の2択にし、どこで切るかと平叙か疑問かを
  **同じ1問・同じ1往復**で選ばせます。
- 選ばれた「、」は「。」か「？」に替えて確定します。字幕・翻訳・読み上げのすべてに効き、
  「？」なら読み上げの語尾が上がります。次の途中結果で「、」に戻らないよう、位置を覚えて
  かけ直します。
- 他の認識（gpt-4o 系・gpt-live）の「、」は本物の読点なので、候補にしません。

## ④ 話し続ける相手でも、判断層の答えが使えるようにする

判断層には2つの壁がありました。

1. **文中の切り所まで「話し終わったか」で止めていた。** 話し続けている限り turn_state は
   CONTINUING になるので、途切れなく話す相手では、Rules の確定を毎回 HOLD の上限
   （2秒）まで遅らせていました。後ろに続きの発話がもう見えている切り所では、「話し終わったか」も
   「いまの無音」も問わないようにしました（Web Speech の文字は音声より1〜3秒遅れて届くので、
   いまの無音はその位置の証拠になりません）。末尾の切り所、安定端（認識が揺れなくなっただけの位置）、言い直し（SELF_REPAIR）は従来どおりです。
2. **答えを「質問したときの版」にしか使えなかった。** 途中結果は0.2秒ごとに伸びるので、往復の
   あいだに必ず版が変わっていました。文中の切り所についての答えは、その前後の文字が同じなら
   次の版でも使うようにしました。HOLD と末尾の答えは持ち越しません。確定で部分の起点が
   動いたら捨てます。

実ブラウザで、記録の会話文（20.5秒分）を、Jev の代わりに規則で答える模擬サーバーで流しました。

| | 最初の確定 | 確定の回数 | 1回の長さ |
|---|---|---|---|
| Rules のみ | 12.0秒 | 2回 | 90字・75字 |
| Jev（模擬） | **4.2〜4.5秒** | 7回 | 13〜33字 |

「作れちゃうんじゃないの**？**」「断ったんじゃなかったっけ**？**」に疑問符が付きました。
**これは模擬の答えです。** 本物の Jev がどこまで正しく選ぶかは、実機の記録で確かめる必要があります。

### 費用の目安

模擬の実行では、約23秒で **41〜44回**（毎秒約2回）質問していました。1回の入力は、実測で
約1,200トークンです（v1.49.23 の記録：入力文4件の12往復で約1万5千トークン）。v1.49.23 の 525回／130秒（毎秒4回・採用0）よりは少なく、今回は使える
答えが返ります。それでも会議1時間では数千回になるので、まずは短い記録で数と採用率を
確かめてください（診断の「判断層の往復」）。

## その他

- 公開 HTML では、経路「Jev — TypeSafe に直接」に「（このページからは不可：CORS）」と表示します。
  api.typesafe.ai は、公開ページからの preflight を 400 Disallowed CORS origin で断ります。
  公開 HTML では「アドオン経由」を使ってください。

## 確かめたこと・確かめていないこと

- 実ブラウザで、途中結果の結合、息継ぎ候補、記号の付け替え、答えの持ち越しを模擬の Jev で
  通しました。
- **本物の Jev での記録はまだありません。** 日本語の話し言葉で文末と疑問を正しく選べるかは、
  実機で確かめる必要があります。まず shadow で記録を取り、Rules と比べてから active に
  上げることをお勧めします。
- Chrome が前半と末尾の境目に空白を入れるかどうかは、確かめられていません。入れない場合でも、
  境目の語が前半へ移った時点で「。」が付くので、以前より遅くなることはありません。
