## Web Speech（日本語）で句読点が付かなかった件

Chrome の Web Speech は、日本語に**句読点を付けません**。代わりに息継ぎの位置へ
**半角スペース**を入れて返します。これまではその空白を句読点に直していなかったため、
次のようになっていました。

```
歴史学という分野とちょっとアプローチが違うんですよね 安全保障論というのは
歴史をモデルとしてみる つまりそれぞれ違う あの。
```

文末の「。」は、最後に確定した一文の末尾にだけ付いていました。区切りは「。」「？」で
切るので、**文末が一つも無いと120字の長さ打切り（`semantic-length-fallback`）まで
切れません**。ログのカードが1枚110〜120字になっていたのはこのためで、翻訳と読み上げも
その分だけ遅れていました。

### 直したこと

空白を、**直前の語尾だけを見て**句読点に置き換えます。

| 直前の語尾 | 置き換え |
|---|---|
| です・ます・でした・ました・ません・でしょう・ください・ですね・ですよ・よね など | 「。」 |
| ですか・ますか・ませんか・でしょうか・だろうか | 「？」 |
| それ以外（「〜みる」「〜違う」「あの」など） | 「、」 |

```
歴史学という分野とちょっとアプローチが違うんですよね。安全保障論というのは
歴史をモデルとしてみる、つまりそれぞれ違う、あの。
```

- **途中結果にもかけます。** 話している最中に「〜ですよね。」で前の文が確定し、
  翻訳が先に進みます（実ブラウザで確認。旧版は79字が1枚のまま最後まで確定せず、
  新版は1文目が話し終わる前に `semantic-sentence` で確定）。
- 後ろの文字は見ないので、**確定済みの前半が後から書き換わることはありません**。
- 「〜みる」「〜違う」のような言い切りは、語尾だけでは文末か文の途中か決められないので
  「、」にとどめます。「まだ」「何か」「静かな」も文末扱いにしません。
- 「Google の」のように**英数字に接する空白は単語の区切り**なので残します（文末なら「。」）。
- 日本語の席だけにかけます。外部API（gpt-4o 系・gpt-live）は句読点付きで返すので触りません。

## Web Speech＋判断層で、Jev が一度も効いていなかった件

同じログで、Jev（active）が**約130秒に525回**呼ばれ、**採用は0件**でした。

判断層の答えは「質問したときの版の文」にしか使えません。Web Speech の途中結果は
**約0.1秒ごとに版が進む**（ログでは revision 427 まで）ので、話している最中に聞くと、
答えが返る頃には必ず別の版になっていて捨てられます。v1.49.20 で入れた
「同じ版を聞き直す上限（3回）」は、版が進み続けると効きません。

**テキストが 0.2秒止まってから聞く**ようにしました（INV-12）。息継ぎのところでだけ
質問が飛ぶので、答えが使える状態で返ります。前の往復が回線を塞いでいない分、
区切りの答えはむしろ早く返ります。確定した文（STT final。録音分割RESTはこちら）は
待たずにすぐ聞きます。

⚙ → 判断層 → **話が止まってから聞くまで ms**（既定200・0で従来どおり）。

## よくある質問

### HTML単独だと「共有しています」のバーが出て、アドオン経由だと出ない

HTML単独では、タブの音声を `getDisplayMedia`（画面共有の仕組み）で取っています。
このバーは Chrome が必ず出すもので、**ページ側から消すことはできません**
（盗聴防止のための Chrome の仕様です）。アドオン経由では `chrome.tabCapture` で
取っているので、このバーは出ません（タブのアイコンに小さな印が出るだけです）。

HTML単独のまま出さない方法は2つです。

- バーの「**非表示**」を押す（共有は続きます）
- 会議アプリの音声を VB-CABLE に出し、⚙→音声で **VB-CABLE入力** を選ぶ
  （マイクと同じ扱いになるので、共有バーは出ません）

### アドオン使用時は Web Speech を使えない？

**使えます。** アドオンで「このタブに字幕表示」を押した状態で HTML本体を開くと
（ワンタッチでも同じ）、HTML本体の共有音声の取得が自動で tabCapture に差し替わります。
Web Speech はその音声を直接認識します（`SpeechRecognition.start(track)`、Chrome 135 以降）。

- 音声認識：**Web Speech**
- 相手の音声入力元：**タブ／システム音声**
- タブ／システム音声の認識方法：「**選択したSTTを使う（通常）**」のままで可
  （他のSTTのまま共有音声だけ Web Speech にするなら「共有音声だけWeb Speechを使う」）

診断に「共有音声=Web Speech Track」と出ていれば、この経路で動いています。
なお、動画タブ側で直接 Web Speech を動かす旧経路は、HTML本体を開いている間は
「音声認識はHTML本体で開始してください」と断ります（二重に認識しないため）。

## 確かめたこと・確かめていないこと

- 実ブラウザ（headless Chromium）で Web Speech の途中結果を1文字ずつ流し、字幕に
  句読点が入ること、1文目が話し終わる前に確定することを確認しました。
  音声認識そのものは試験環境で動かないので、**実際の Chrome の空白の入り方**では
  確かめていません。
- 判断層の待ちは試験で固定しましたが、Jev 経由の実機記録はまだありません。
